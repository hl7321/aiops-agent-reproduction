# Design

## Context

见 `proposal.md - Why`。当前实现里，执行者把 `From`/`To` 交给模型填，模型每次的取值不一致；fixture 又把日志时间放在上传之后，二者叠加让同一场景的结果不可复现。CLS 主题保留期为 30 天，上传到可检索的延迟本次实测约 1 分钟。

需求见 `specs/schema-aware-aiops-tool-execution/spec.md` 与 `specs/correlated-ecommerce-aiops-fixtures/spec.md`。

## Goals / Non-Goals

**Goals：**

- 同一条告警、同一批日志，时间窗每次都一致；
- 默认演示流程（上传 → 发告警 → 诊断）不需要手工计算时间；
- 已上传的日志在 30 天内可以反复用于验证。

**Non-Goals：**

- 不解决 PkgId/PkgLogId 的产生方式；
- 不改变 CLS 保留策略；
- 不调整上下文与模型选择。

## Decisions

### 1. 时间窗在 executor 装配参数时计算，不让模型参与

新增窗口偏移配置（before=15、after=0，单位分钟）。执行 SearchLog 前，从本轮告警的 `startsAt` 取最早与最晚值，计算 `[min − before, max + after]`，再传给参数装配函数。

备选：让模型继续算、服务端只做校验。仍会保留"模型算错日期/方向"这一类故障，且无法保证复现，因此不采用。

### 2. `From`/`To` 与 Region/TopicId 一样对模型隐藏

把 SearchLog 的 `From`/`To` 加入服务端注入字段集合：模型可见 schema 不再包含它们，必填列表也同步移除；模型即使输出也会被丢弃，并由服务端值覆盖。

备选：保留字段但改写取值。会让模型把 token 花在它无法决定的值上，也容易误导它去"修"时间窗，因此不采用。

### 3. 告警时间不可解析时明确失败

缺少或无法解析 `startsAt` 时，在调用 SearchLog 前抛出配置类错误，使该步骤以 `configuration` 类别失败；不退回"模型猜一个时间"或"用当前时间"。

备选：回退到 `now`。会让测试与演示在告警输入异常时悄悄通过，掩盖真实问题。

### 4. fixture 日志时间改为上传时刻之前

十套 incident 依次放在 `T−9 ~ T` 分钟，每套内部四段日志仍按秒递增。这样默认 `[告警时刻 − 15 分钟, 告警时刻]` 能覆盖全部日志，且语义是"先发生故障、后触发告警"。

备选：保持日志向前排、要求告警用 `--starts-at` 对齐。作为默认路径太依赖人工操作，因此只作为补充能力保留。

### 5. 发布脚本新增 `--starts-at`

接受带时区的 ISO 8601 时间（支持 `Z`），统一转换成 UTC 后作为十条告警的 `startsAt`；`endsAt` 固定加 2 小时。缺时区或无法解析时在任何网络请求前失败。

备选：只允许相对偏移（如 `--offset-minutes`）。表达力不如绝对时间，且不利于重放历史场景。

### 6. 演示告警有效期可配置，并提供 ensure

默认仍为 2 小时，避免把"常驻告警"变成隐蔽默认行为；演示时显式传 `--active-days 30`。`--ensure` 先读取当前活跃告警，已有 10 条就跳过 POST，重复执行不会制造重复告警。

备选：应用启动时自动发布告警。会引入隐式外部副作用，且启动脚本无法区分"演示环境"与真实环境，因此不采用；容器重启后由用户显式执行一次 ensure。

## Risks / Trade-offs

- **多告警跨度很大时窗口变宽** → 先按 min/max 计算，不额外裁剪；若后续日志量过大，再增加"最大窗口"配置。
- **旧配置没有新字段** → 两个窗口字段都有默认值，旧配置无需改动即可运行。
- **fixture 时间改向后旧测试断言会失败** → 同步更新脚本测试，明确断言时间范围。
- **模型可见字段减少** → `visible_argument_names` 与必填校验需同步；用单测固定"From/To 不在模型 schema"。
- **PkgId 规格漂移修正可能被误读为功能变化** → 在规格中明确"当前上传链路不保证 PkgId，DescribeLogContext 不在本 Profile 的可用保证内"，不改变工具代码。
- **Alertmanager 重启会清空告警** → `--ensure` 可安全重复执行；README 写明容器重启后的补齐命令，不在应用启动时自动发布。

## Migration Plan

1. 先加配置字段与默认值（向后兼容）；
2. 部署后端与服务端注入逻辑；
3. 部署脚本的 fixture 时间与 `--starts-at`；
4. 已有 CLS 日志不受影响；新上传的日志使用新的时间排布；
5. 回滚：恢复代码即可，无数据库迁移。
