# Design

## Context

见 `proposal.md - Why`。会话标题在首条 user 消息时自动生成且之后不可改；摘要为自由文本；右栏摘要在列表下方常驻。

## Goals / Non-Goals

**Goals：**

- 会话可显式重命名，且不被首条消息覆盖；
- 摘要固定六段，前端可按段展示；
- 摘要改为按会话就地展开的卡片，默认不展示；
- 保持旧摘要可读。

**Non-Goals：**

- 不改压缩窗口、阈值或自动压缩策略；
- 不做摘要编辑、搜索或版本历史；
- 不引入右键菜单。

## Decisions

### 1. 重命名走 PATCH，标题上限 128

新增 `PATCH /chat/sessions/{id}`，请求 `{title}`。标题 trim 后 1..128 字符，按 owner scope 更新并刷新 `updatedAt`。`chat_sessions.title` 已是 VARCHAR(128)，无需迁移。

### 2. 显式重命名优先于自动标题

现有自动标题逻辑在"首条 user 消息且此前没有 user 消息"时写入前 48 字。本次改为：**只有当前标题仍为默认"新会话"时才自动生成**；用户显式重命名后，首条消息不得覆盖。

备选：新增 `title_source` 列区分自动/手动。需要迁移且收益有限，不采用。

### 3. 左侧使用行内编辑按钮，不做右键菜单

每个会话行改为"选择按钮 + 编辑图标按钮"的结构（避免 button 嵌套）。点击编辑进入 input，Enter 保存、Esc 取消；失败保留服务端标题并显示错误。按钮比右键菜单更易发现、可键盘操作、触屏可用。

### 4. 摘要固定六段 Markdown

摘要保持 `TEXT` 字段，不新增结构化列。固定标题为：

1. `## 对话目标`
2. `## 关键事实与标识`
3. `## 已做决定`
4. `## 工具与证据`
5. `## 未解决事项`
6. `## 风险与注意事项`

每段短 bullet；空段写"（无）"。在已有四段（事实/决定/工具证据/未解决）之外，增加"对话目标"与"风险与注意事项"，并把 OnCall 关键标识（服务、告警、incident/trace、时间）明确放进"关键事实与标识"。

后端 summarizer prompt 要求该结构；`ChatMemoryService` 对模型输出做归一化：保留已有六段，缺失段补"（无）"；完全无标题的旧摘要不重写，交给前端按"摘要"兼容。

### 5. 摘要卡片就地展开

参照 AIOps 沉淀案例：会话行下方渲染 `<article class="summary-card">`，只对当前选中会话显示；再次点击同一行或"收起"关闭。卡片内按六段渲染；旧摘要渲染为单一"摘要"段。摘要不再常驻列表底部。

## Risks / Trade-offs

- **六段使摘要更长**：每段 1-3 条 bullet，限制总长度；空段写"（无）"避免模型省略。
- **模型不遵守标题** → 后端归一化补段；前端对未知/缺失标题降级为"摘要"。
- **重命名排序变化**：更新 `updatedAt` 会使会话移动到列表顶部；这是明确的产品选择。
- **行内编辑与选择冲突** → 编辑按钮 `stopPropagation`，行本身仍负责选择。
- **旧摘要无结构** → 前端兼容，不强制重压缩。

## Migration Plan

无数据库迁移；`memory_summary` 继续存 Markdown 文本。回滚只需恢复代码。
